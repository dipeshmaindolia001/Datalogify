question: |
  Write a SQL query to find employees who have the highest salary in each of the departments.
sampleData: |
  `Employee` table:
  | id | name | salary | departmentId |
  |---|---|---|---|
  | 1 | Joe | 70000 | 1 |
  | 2 | Jim | 90000 | 1 |
  | 3 | Henry | 80000 | 2 |
  | 4 | Sam | 60000 | 2 |
  | 5 | Max | 90000 | 1 |

  `Department` table:
  | id | name |
  |---|---|
  | 1 | IT |
  | 2 | Sales |
answer: |
  Using a Window Function (`DENSE_RANK`):
  ```sql
  WITH RankedSalaries AS (
      SELECT 
          d.name AS Department,
          e.name AS Employee,
          e.salary AS Salary,
          DENSE_RANK() OVER(PARTITION BY e.departmentId ORDER BY e.salary DESC) as rnk
      FROM Employee e
      JOIN Department d ON e.departmentId = d.id
  )
  SELECT Department, Employee, Salary
  FROM RankedSalaries
  WHERE rnk = 1;
  ```
explanation: |
  - We first join the `Employee` and `Department` tables to resolve department names.
  - We use a Common Table Expression (CTE) and the `DENSE_RANK()` window function to assign a rank to employees in each department, partitioning by department and ordering by salary descending.
  - Finally, we select the records where the rank is `1`, which retrieves all employees with the highest salary (including ties).
followUp: |
  Why use `DENSE_RANK()` instead of `ROW_NUMBER()` or `RANK()`?
  - `ROW_NUMBER()` does not handle ties (it will arbitrarily assign a 1 and 2 to ties).
  - `RANK()` and `DENSE_RANK()` both handle ties by assigning the same rank value. However, `RANK()` skips rank numbers after a tie (e.g. 1, 1, 3), whereas `DENSE_RANK()` keeps them contiguous (e.g. 1, 1, 2). For retrieving ties at rank 1, both work, but `DENSE_RANK()` is generally preferred for ranking categories.
