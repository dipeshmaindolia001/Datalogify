question: |
  Write a SQL query to find all customers who never order anything.
sampleData: |
  `Customers` table:
  | id | name |
  |---|---|
  | 1 | Joe |
  | 2 | Henry |
  | 3 | Sam |
  | 4 | Max |

  `Orders` table:
  | id | customerId |
  |---|---|
  | 1 | 3 |
  | 2 | 1 |
answer: |
  Using a `LEFT JOIN`:
  ```sql
  SELECT c.name AS Customers
  FROM Customers c
  LEFT JOIN Orders o ON c.id = o.customerId
  WHERE o.customerId IS NULL;
  ```

  Using `NOT IN` (or `NOT EXISTS`):
  ```sql
  SELECT name AS Customers
  FROM Customers
  WHERE id NOT IN (
      SELECT DISTINCT customerId 
      FROM Orders 
      WHERE customerId IS NOT NULL
  );
  ```
explanation: |
  - In the `LEFT JOIN` approach, we join all customers with their orders. Customers who never placed an order will have `NULL` values for the columns from the `Orders` table. We filter for these using `WHERE o.customerId IS NULL`.
  - In the subquery `NOT IN` approach, we retrieve customer IDs from the `Orders` table, and select customers from the `Customers` table whose IDs do not exist in that set. We filter out `NULL` values in the subquery to ensure `NOT IN` functions correctly.
followUp: |
  What is the performance difference between `LEFT JOIN` and `NOT EXISTS` in large datasets?
  - Generally, database engines optimize `NOT EXISTS` better when searching for non-matching records because it can short-circuit as soon as it finds a single match, whereas `LEFT JOIN` may perform a full join operation before filtering.
