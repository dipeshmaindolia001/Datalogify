question: |
  A country is considered **big** if it has an area of at least 3 million km² or a population of at least 25 million. Write a SQL query to report the name, population, and area of the big countries.
sampleData: |
  `World` table:
  | name | continent | area | population | gdp |
  |---|---|---|---|---|
  | Afghanistan | Asia | 652230 | 25500100 | 20343000000 |
  | Albania | Europe | 28748 | 2831741 | 12960000000 |
  | Algeria | Africa | 2381741 | 37100000 | 188681000000 |
  | Andorra | Europe | 468 | 78115 | 3712000000 |
answer: |
  Using `OR`:
  ```sql
  SELECT name, population, area
  FROM World
  WHERE area >= 3000000 OR population >= 25000000;
  ```

  Using `UNION` (which is often faster if there are separate indexes on both fields):
  ```sql
  SELECT name, population, area
  FROM World
  WHERE area >= 3000000
  UNION
  SELECT name, population, area
  FROM World
  WHERE population >= 25000000;
  ```
explanation: |
  - The first approach uses a standard `WHERE` clause combining both logical predicates with `OR`.
  - The second approach uses `UNION` to combine results from two separate queries. In some databases, this allows the query optimizer to utilize indexes on both `area` and `population` columns separately, bypassing the full-table scan that an `OR` condition might otherwise trigger.
followUp: |
  When is it better to use `UNION` instead of `OR`?
  - `UNION` is typically preferred for large tables when both search conditions are indexed. Using `OR` can make the query optimizer ignore indexes and do a full table scan.
