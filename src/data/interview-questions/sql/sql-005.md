question: |
  Write a SQL query to calculate the month-over-month user retention rate. For each month, compute the percentage of active users who were also active in the previous month.
sampleData: |
  `UserActions` table:
  | userId | actionDate |
  |---|---|
  | 1 | 2026-01-10 |
  | 2 | 2026-01-15 |
  | 1 | 2026-02-12 |
  | 3 | 2026-02-20 |
  | 2 | 2026-02-28 |
  | 3 | 2026-03-05 |
answer: |
  ```sql
  WITH MonthlyActiveUsers AS (
      SELECT DISTINCT
          userId,
          DATE_TRUNC('month', actionDate) AS active_month
      FROM UserActions
  )
  SELECT
      TO_CHAR(curr.active_month, 'YYYY-MM') AS month,
      COUNT(DISTINCT prev.userId) AS retained_users,
      COUNT(DISTINCT curr.userId) AS total_active_users,
      ROUND(
          COUNT(DISTINCT prev.userId) * 100.0 / COUNT(DISTINCT curr.userId), 
          2
      ) AS retention_rate
  FROM MonthlyActiveUsers curr
  LEFT JOIN MonthlyActiveUsers prev ON 
      curr.userId = prev.userId AND 
      curr.active_month = prev.active_month + INTERVAL '1 month'
  GROUP BY curr.active_month
  ORDER BY curr.active_month;
  ```
explanation: |
  - We first write a CTE `MonthlyActiveUsers` to get unique user activity per month, using `DATE_TRUNC` to standardize dates to the first of the month.
  - We perform a `LEFT JOIN` of the CTE with itself, matching the user IDs where the current month matches the previous month plus a 1-month interval.
  - If a user was active in the current month but not the previous month, the joined columns will be `NULL`.
  - We group by the current month and calculate the percentage of matching joined users (`retained_users`) over total active users in the current month.
followUp: |
  How would you modify this query to track weekly cohort retention?
  - You would normalize action dates to the start of the week (e.g., using `DATE_TRUNC('week', actionDate)`) and join matching users active in the current week with those who signed up in their initial signup week, grouping by the signup cohort.
